# AI 知识采集协议

## 定位

本文档是随知识库持久化的治理说明，使项目在更换 Agent 或未安装 Context Atlas Skill 时仍可被理解和人工维护。它不是插件完整运行时规范，不定义插件命令、运行时探测或平台适配细节。

已安装 Context Atlas Skill 时，Agent 应先按 Skill 加载其随附的平台无关执行协议；Skill 是薄编排入口，Schema 是文档结构和状态的机器权威。未安装 Skill 时，至少遵守本文下列的读取、Proposal、确认、冲突、安全和报告规则。

## 读取顺序

README → 本协议 → 与用户请求相关的需求、功能、契约、ADR 和验收项；存在关联变更、验收证据或外部任务引用时再按需读取。

## Proposal

Agent 调研仓库和已有文档后，向用户展示：当前修订标识、目标位置、发现事实及来源、推断、未知项、冲突、拟写文件、影响、技术栈记录和验证方式。用户明确确认当前修订前不得正式写入，也不得把 Proposal 写成 `approved`；目标、事实、关系、影响或验证变化时必须重新确认。

## 写入规则

- 事实附内嵌来源；来源至少记录类型、精确引用、观察时间和确认状态，已确认来源还记录确认时间；推断标记 `ai_inference`。
- 冲突保留至少两个来源，并指定需要谁裁决。
- 批准项记录确认人、确认时间和版本。
- 沉默不是确认；Agent 不得把自己登记为批准人。
- 替代旧知识时保留确有审计价值的历史并建立双向引用；迁移当前引用并验证后，以包含路径和摘要的已确认提案执行归档，失败时完整回滚。
- 密码、Token、私钥和未脱敏个人数据不得写入；配置只记录 `${ENV_VAR}` 形式。

Agent 完成后报告写入路径、记录的技术栈、确认状态、检查结果、未解决项和下一步。检查通过只表示结构和引用满足规则，不表示内容已被正确批准。若初始化 Proposal 明确当前宿主，可按宿主映射创建或补充 `AGENTS.md` 或 `CLAUDE.md` 的 Context Atlas 受管区块；不得覆盖其他项目规则。

知识库不决定外部任务能否执行。任务可以来自用户、Superpowers、OpenSpec、Issue 系统或其他 Agent；Context Atlas 只在正式知识写入时执行提案、确认、来源、影响和验证规则。

## 主动检查点

只有用户明确要求维护、同步或迁移知识库时，Agent 才进入 Proposal 和写入流程。普通开发可以提示发现候选，但不得自动创建提案文件、调用更新 Skill、修改正式知识或阻塞外部任务。

只有用户明确要求把候选持久记录下来时，才可在 `03-变更与证据/待确认知识/` 创建 `PROP-*`；否则只在当前对话中提示。候选记录内容提出者、Agent 操作方和待确认人。人员候选可从仓库本地 Git 用户名和邮箱摘要匹配；未匹配或多重匹配时使用 `PERSON-UNKNOWN`，不能猜测。
