# 关系目录

<!-- context-atlas-rules: [[rules/知识治理规则#RULE-REL-002|RULE-REL-002]] -->

本文只解释项目中正式关系的写法。关系类型的机器权威目录位于 `.project-kb/schemas/relation-catalog.json`。

## 统一写法

```yaml
rel_satisfies:
  - "[[01-功能基线/REQ-001-订单需求|REQ-001]]"
rel_reads:
  - "[[02-架构与契约/数据库/TABLE-ORDER-001#FIELD-ORDER-STATUS 状态|FIELD-ORDER-STATUS]]"
```

- `rel_<type>` 表示登记过的正向关系类型。
- `相对/目标文件` 从知识库根目录开始，不写 `.md` 也可以。
- 聚合文件中的知识项必须写完整标题锚点或块锚点。
- `TARGET-ID` 必须与目标文件或目标锚点声明的稳定编号一致。
- 不写裸编号关系、嵌套 `relations` 和人工反向列表；反向使用方由检查器计算。

运行 `.project-kb/scripts/check_knowledge_base.py` 检查链接、编号、锚点和方向。文件移动后，先更新所有正向链接，再运行检查和影响分析。
