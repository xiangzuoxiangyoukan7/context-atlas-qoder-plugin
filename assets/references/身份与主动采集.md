# 身份与主动采集

## 人员身份

可选人员登记位于 `05-知识治理/协作与责任.md`。只有项目需要稳定人员编号时才创建；先读取仓库本地 Git 用户名和邮箱，只用它们匹配候选，Git 邮箱摘要使用规范化邮箱的 SHA-256 值，知识库不保存完整邮箱。

- 唯一匹配：提案的 `proposed_by`（内容提出者）使用稳定 `PERSON-*` 编号。
- 未匹配或多重匹配：使用 `PERSON-UNKNOWN`，提示用户确认后再维护人员表。
- `operated_by`（文件操作方）记录 `AGENT-CODEX`、`AGENT-CLAUDE-CODE` 等 Agent 编号。
- `confirmed_by`（内容确认者）必须来自明确确认，不能从 Git 或操作者身份推断。

使用统一命令读取当前仓库配置并匹配知识库人员表：

```text
python <知识库>/.project-kb/scripts/agent_kb_operation.py identify-contributor <项目仓库> <知识库>
```

报告为 `candidate`（新候选）或 `ambiguous`（存在歧义）时使用 `PERSON-UNKNOWN`，并向用户确认；命令不会自动修改人员表或 Git 配置。

## 什么时候主动捕获

Agent 在下列自然检查点检查是否出现新的项目知识：

| 检查点 | 中文含义 |
| --- | --- |
| `user_decision` | 用户作出明确决策后 |
| `requirement_change` | 需求发生变化后 |
| `contract_change` | 接口或数据契约发生变化后 |
| `before_plan` | 开始实施计划前 |
| `before_delivery` | 准备交付前 |
| `after_acceptance` | 取得验收结果后 |
| `before_release` | 项目发布前 |
| `session_end` | 当前会话结束前 |

没有新知识时不创建文件。有新知识时，只保存摘要、目标稳定编号、来源位置、差异、可能影响、未知项和冲突，不复制 Superpowers、OpenSpec 或其他插件的过程文件全文。

## 如何写入待确认队列

使用统一命令；同一目标和同一摘要会自动去重：

```text
python <知识库>/.project-kb/scripts/agent_kb_operation.py capture <知识库> --checkpoint user_decision --summary "摘要" --target-id REQ-001 --source-type user_statement --source-reference "当前用户明确决定" --difference "与现状的差异" --impact-id FEATURE-001 --proposed-by PERSON-001 --operated-by AGENT-CLAUDE-CODE --project-version 1.2.0 --captured-at 2026-08-13T10:30:00+08:00 --user-requested
```

命令只能创建 `status: proposed` 的 `PROP-*` 文件。它不修改正式需求、功能、接口或数据库知识，不控制开发任务是否执行，也不等于用户批准。之后仍按“提案—明确确认—正式写入—验证”处理。
