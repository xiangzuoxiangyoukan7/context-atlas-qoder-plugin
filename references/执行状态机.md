# 执行状态机

<!-- context-atlas-rules: [[rules/知识治理规则#RULE-AGENT-001|RULE-AGENT-001]] [[rules/知识治理规则#RULE-GOV-003|RULE-GOV-003]] -->

所有会正式写入知识库的操作使用同一条状态链：

`inspect -> propose -> await_confirmation -> apply -> validate -> report`

| State | Required output | Next-state gate |
| --- | --- | --- |
| `inspect` | 已解析的项目根、目标知识库、现有文件、来源、冲突和未知项 | 只读检查完成后进入 `propose` |
| `propose` | 带 `proposal_revision` 的目标、事实、关系、影响和验证计划 | 完整提案展示后进入 `await_confirmation` |
| `await_confirmation` | 用户确认内容及 `confirmed_revision` | 仅当 `proposal_revision == confirmed_revision` 时进入 `apply` |
| `apply` | 只写已确认目标的文件清单 | 写入完成后进入 `validate` |
| `validate` | 实际命令、退出码、问题数和报告位置 | 验证命令确实完成后进入 `report` |
| `report` | 操作、写入、确认、验证、未知项、冲突和下一步 | 终态 |

## 写入门禁

在 `await_confirmation` 中没有当前修订的明确确认时，要求是 **zero formal writes**：不得创建、修改、移动、归档或迁移正式知识文件。临时分析不得伪装成正式知识；提案的目标、事实、关系或影响发生变化时，增加 `proposal_revision` 并重新确认。

`validate` 失败时仍进入 `report`，但报告结果必须是失败，不能声称操作成功。没有运行验证时使用 `not_validated`，不能用旧输出代替。

## 初始化分支

如果初始化目标已存在，停在 `inspect`，报告冲突并切换到更新流程。不得覆盖、合并初始化或用新模板重建已有知识库。

## 职责边界

此状态机只控制 Context Atlas 对知识库的正式写入，不决定外部任务是否执行。Superpowers、OpenSpec 或其他任务插件可以管理开发任务；知识库只在出现可保存的项目知识时采集、确认和验证知识。
