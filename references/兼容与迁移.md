# 兼容与迁移

## 两种版本各管什么

- `project_version`（项目版本）跟随业务项目发布，例如 `1.4.0`。
- `format_version`（知识库格式版本）只表示文档结构和字段规则，例如从旧的裸来源编号升级为文件链接。

插件升级和知识库升级是两个独立动作。安装新版插件不会自动修改项目知识库。用户明确要求“升级知识库”时，以当前已安装插件 `assets/compatibility.json` 为升级版本权威；其中 `manifest_version` 描述兼容清单结构，`supported_format_versions` 描述可读格式，`created_format_version` 描述新建格式。目标知识库 `.project-kb/compatibility.json` 只记录其内嵌运行资产生成时认识的格式，不能用来判断当前插件是否提供更新转换，否则旧知识库会用旧规则误判自己“无需升级”。可读且无需转换的旧格式继续直接使用，只有文档表达逻辑变化时才做等价转换，不为了追求最新版而强制改写。未知格式必须停止正式写入并报告，不得猜测。

“升级知识库”只升级 `format_version` 所代表的知识表达结构，不新增、修改或批准业务事实。只有 `format_version` 参与兼容判断；产品版本、`project_version`、`knowledge_revision` 和领域对象版本不构成兼容门禁。新增需求、修订接口、同步数据库事实等属于“维护知识”，不是格式升级。

## 只读诊断

从当前已安装 Skill 位置解析 `<当前插件 assets>`，在知识库根目录的父目录执行：

```text
python <当前插件 assets>/scripts/agent_kb_operation.py upgrade-diagnose <知识库> --compatibility <当前插件 assets>/compatibility.json
```

报告中的 `runtime_assets_root` 和 `compatibility_path` 必须指向当前已安装插件，不能位于目标知识库 `.project-kb/` 内。`write_blocked`（是否禁止正式写入）为 `false` 才可继续知识更新。`conversion_available`（是否存在转换器）为 `true` 只表示可以提出迁移，不表示已获批准。

## 轻量转换

诊断为 `compatible` 时直接报告“无需升级”，保持零写入。诊断为 `conversion_available` 时运行 `upgrade-propose`（生成升级提案）：

```text
python <当前插件 assets>/scripts/agent_kb_operation.py upgrade-propose <知识库> --compatibility <当前插件 assets>/compatibility.json
```

向用户展示源格式、目标格式、完整变更文件、移动/删除项、未解析项和 `proposal_revision`（提案修订号）。只有用户明确确认同一修订号且未解析项为空，才运行 `upgrade-apply`（应用升级）：

```text
python <当前插件 assets>/scripts/agent_kb_operation.py upgrade-apply <知识库> --compatibility <当前插件 assets>/compatibility.json --proposal-revision <修订号> --confirmed-revision <同一修订号>
```

应用前必须重新计算提案并核对修订号，防止确认后文件已变化。应用应原子完成；失败时恢复原文件。应用后运行完整知识库检查器，并报告最终 `format_version`、实际修改路径和未解决项。旧命令 `diagnose-format`、`migrate-propose`、`migrate-apply` 仅作为兼容别名保留，新流程不得再用它们向用户解释“更新知识”。

格式 1、2、3 转换到当前格式时，将能够唯一定位的旧 `sources: [SRC-*]` 替换为知识项内嵌来源对象，包含来源类型、精确引用、观察时间、确认状态和必要的确认时间。可选公共来源迁入 `05-知识治理/公共来源/`，但不再是理解单项知识的前置条件。转换同时将治理入口迁入 `05-知识治理/`，并仅删除可证明为旧模板占位内容的“本地开发”和“测试规则”文件。

格式 4 及后续旧格式升级时保留旧物理布局读取兼容，并将旧 `rel_implements` 确定性改为 `rel_satisfies`。格式 8 统一根清单版本模型：删除根级 `protocol_version`、`schema_version`，将 `revision` 等价改名为 `knowledge_revision`，增加可选生成工具追踪；旧知识项 `version` 在一个兼容周期内继续读取，无法安全分类时不得猜测。转换不得改变 `project_version`、业务含义、批准状态、来源、稳定 ID 或历史。
