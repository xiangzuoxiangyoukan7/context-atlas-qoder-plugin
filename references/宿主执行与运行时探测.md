# 宿主执行与运行时探测

## 能力预检

在 `inspect` 阶段先确认 Agent 宿主能够读取、创建、枚举、比较并重命名项目根目录内的文件。缺少任一能力时保持 zero formal writes，不得进入 `apply`。

通过宿主命令执行能力实际探测 Python 3，不能只检查命令名称或 PATH：

- Windows 依次尝试 `py -3`、`python`、`python3`；
- POSIX 依次尝试 `python3`、`python`；
- 每个候选都执行 `-c "import sys; print(sys.executable); print(sys.version_info.major)"`；
- 只有退出码为 `0` 且主版本为 `3` 才可选择；Windows Store 占位入口返回 9009 视为失败并继续探测；
- `uv` 和 Conda 是可选来源，不是前置依赖。

只记录候选命令、结果、退出码和主版本；不得记录完整 PATH、环境变量或其他敏感环境信息。

结构化执行器必须自行以 UTF-8 解码标准输入并以 UTF-8 输出 JSON，不得依赖 Windows 当前代码页或要求用户预先设置 `PYTHONUTF8`、`PYTHONIOENCODING`。宿主负责按字节传递 UTF-8 Proposal；中文内容或路径编码失败属于执行失败，不能改成未声明的手工写入。

## 执行模式

Python 3 可用时选择 `python_executor`，使用同一已验证命令执行 apply 和 validate。报告使用 `validation.authority: deterministic_executor`，并按实际结果记录 `deterministic_validation: passed` 或 `failed`。

Python 3 不可用时选择 `agent_host`。该模式只能在当前 Proposal 修订已明确确认后使用，并遵守以下事务边界：

1. 重新确认正式目标不存在，记录项目写入前的已有文件路径；Git 可用时同时记录 `git status --short`，但不得把 Git 作为唯一证据。
2. 在项目根的固定 `.context-atlas-temp/` 临时根下创建唯一的 `initialize-<revision-prefix>/` 操作子目录；所有暂存产物只能位于该子目录，不得在项目根散落其他临时目录，也不得在知识库正式内容目录中创建与固定临时根同级的随机临时目录；不得直接写正式目标。未来新增操作同样必须在该固定临时根内使用操作专属子目录。
3. 只从 `../../assets/templates/core/doc-project/` 复制模板，只替换 `{{PROJECT_ID}}`、`{{PROJECT_NAME}}`、`{{KNOWLEDGE_BASE_NAME}}` 和 `{{INITIALIZED_AT}}`，并按已确认 Proposal 渲染内容。
4. 将 `../../assets/scripts/`、`../../assets/schemas/` 和 `../../assets/compatibility.json` 复制到暂存目标的 `.project-kb/`，以便以后可进行确定性复验。
5. 使用宿主读取和搜索能力验证：预期文件全部存在、没有未声明文件、没有 `{{UPPER_CASE_MARKER}}`、JSON/YAML/frontmatter 可读、受控 ID 不重复、内部目标引用存在；默认写入范围只包含暂存目录，若 Proposal 明确了 `agent_entry`，再核对对应入口文件仅新增或更新 Context Atlas 受管区块。
6. 任一检查失败时保留正式目标不存在，清理本次操作子目录并报告失败；不得把暂存结果声明为知识库。
7. 全部宿主检查通过且正式目标仍不存在时，使用一次同文件系统重命名把暂存目标移动为正式目标，清理本次操作子目录，然后再次核对项目差异只包含正式目标和固定临时根。

`agent_host` 报告必须使用 `validation.authority: agent_host`、`deterministic_validation: not_run`，并列出每项宿主检查。宿主检查通过可以报告初始化完成，但不得表述为“确定性验证通过”。以后发现 Python 3 或 CI 检查器时，应运行目标内置检查器进行增强复验。
